tutuca-mb

Open the playground Edit a book of stories in MoonBit and run it with the storybook's panels: it compiles in your browser.

Examples

Each one compiles in your browser when it scrolls into view. Edit it and press Ctrl+Enter; the storybook on the right steps through its sequences, stress tests it and shows its state. Their sources are packages in site/, which moon test checks; each also opens in the playground.

1. A counter

A component is a state type, a message type, a view and an update. Its story replays a sequence of clicks.

2. A todo list

A collection, a loop, form inputs and a computed value.

3. Components inside components

A cart renders its lines, which notify it when they go; an invariant is checked after every message.

4. Asks

A component asks; a handler in a scope answers, now, later or never.

5. Mistakes

What the compiler catches, underlined in the editor, then what Component::check() reports.

Demos

  • ✅ Todo: projects, labels, priorities, subtasks and quick add (wasm-gc).
  • 📈 Thing tracker: log habits, moods and drinks; see insights (wasm-gc).
  • 📝 Payload → Schema: edit a payload, get a documented JSON Schema (wasm-gc).
  • 🎨 Sketchpad: shapes, layers, undo and save as SVG (wasm-gc).
  • ➗ Algebra workbench: quadratics with their plot, 2×2 matrices (wasm-gc).
  • 🔢 Counters in elements: apps in <tutuca-app> shadow roots, reporting to the page (wasm-gc).
  • 📚 Storybook: every story, live, with its steps, timeline and stress tests (wasm-gc).

The js pages run the moon js build; the wasm-gc ones the same components compiled to wasm-gc, through wasm/loader.mjs.
