Tutuca

A SPA framework for humans and agents.

A full implementation that fits in your head and the context window.

Open the storybook Demos GitHub

Tutuca is a complete frontend framework, not just a view layer. Components, typed state, rendering and event routing come with everything you need to trust them: headless tests, property-based tests derived from your schemas, a storybook that stress tests your stories, a linter, and a formal specification of the semantics in PLT Redex.

The core is about 1,800 lines with no runtime dependencies. You can read all of it in an afternoon, and an agent can hold all of it at once.

📦

Install

npm install tutuca@next

Or import it from a CDN, no build step:

import { component, h, Host } from "https://cdn.jsdelivr.net/npm/tutuca@next/dist/tutuca.min.js";

A first component

const Counter = component({
  name: "Counter",
  fields: (t) => ({ count: t.number() }),
  view: h("button", { "@on.click": send("inc") }, "Clicked ", field("count")),
  on: {
    inc(draft) {
      draft.count += 1;
    },
  },
});

const host = new Host({ document, rootNode: document.getElementById("app") });
host.scope.register({ Counter });
host.start(host.scope.components.Counter());

Build

  • 🧱
    Components with typed state

    Fields are schemas: strings, numbers, enums, options, arrays, maps, records, unions and nested components.

  • 🌳
    Views as data

    h, each, render, $if and scope build a tree the framework can inspect, lint and optimize.

  • ✉️
    Messages, not callbacks

    Events send typed messages along explicit paths to the component that handles them.

  • 🧊
    Immutable updates

    Handlers edit a draft; state stays immutable, so time travel and diffing are free.

  • ⚡
    A small, fast vdom

    Keyed reconciliation, with constant subtrees hoisted out of re-renders.

  • 🪟
    Embeddable

    A <tutuca-app> custom element runs apps isolated in a shadow root.

Test

  • 🤖
    Headless testing

    A driver runs messages through the real task loop with or without a DOM, and reports failed tasks and invalid state.

  • 🎲
    Property-based tests from your schemas

    Random states, messages and DOM events are generated from the field and message types you already wrote.

  • 📚
    Storybook built in

    Stories with step sequences, a timeline to step back and forth, and stress tests that find and replay counterexamples.

  • 🧹
    Lint and invariants

    Catch unknown fields, views, components and handlers, and mistyped message arguments, before running. In dev, state and invariants are checked after every update.

Understand

  • 📐
    A formal specification

    A PLT Redex model of views, rendering, reconciliation, paths and the task queue, typeset as a PDF. in progress

  • 🔍
    DevTools formatters

    Components, paths and tasks show up readable in the browser console.

  • 🪶
    Fits in your head

    About 1,800 lines of core, 16 KB minified and gzipped, no runtime dependencies.

  • 🧠
    Fits in the context window

    Small enough for an agent to read the whole framework before writing a line.
